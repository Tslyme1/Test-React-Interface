# Уралмаш — подбор конусных дробилок КМД/КСД

React-приложение на дизайн-системе [`@uralmash/design-system`](https://github.com/Tslyme1/design-system).
Перенесено со статического прототипа «Claude Design» (`legacy-prototype/`) — см. ниже, что уже перенесено
и что осталось.

## Как посмотреть и потестировать

Три варианта, от самого быстрого к самому «настоящему»:

1. **Ничего не ставить.** Собранная версия текущей ветки лежит в виде Artifact —
   откройте её прямо в браузере и кликайте: [Дробилки КМД-КСД](https://claude.ai/code/artifact/2b712e1d-ff23-48b6-8eda-c80fa01622b9).
   Это статический снимок на момент сборки — правки в коде сюда сами не попадают,
   нужно пересобирать (`npm run build:demo`) и публиковать заново.
2. **Деплой из GitHub, обновляется на каждый push.** Workflow
   `.github/workflows/deploy-pages.yml` собирает и выкладывает приложение на
   GitHub Pages при пуше в `main` или в эту ветку. **Нужно один раз включить
   вручную:** Settings → Pages → Source → «GitHub Actions» в репозитории —
   без этого шага Actions выведет ошибку «Pages site failed». После этого адрес —
   `https://tslyme1.github.io/Test-React-Interface/`, обновляется сам.
3. **Локально.**
   ```bash
   npm install   # подтягивает @uralmash/design-system из GitHub и собирает её (postinstall)
   npm run dev   # http://localhost:5173
   ```

```bash
npm run typecheck   # tsc --noEmit
npm run build        # typecheck + сборка в dist/ (обычный деплой)
npm run build:demo   # автономная сборка в dist-demo/index.html — один файл,
                      # без сервера, для Artifact/вложений
```

## Демо-доступы

Мок-авторизация без реального пароля на сервере — учётные данные тестовые:
`ivanov/1234`, `petrova/1234`, `admin/admin` (роль «Администратор + инженер»). Любой другой
логин/пароль тоже пускает внутрь — так было устроено уже в исходном прототипе.

## Что перенесено (core-флоу)

- Вход / выход, мок-сессия (`localStorage`).
- Список проектов: поиск, сортировка, удаление, пустое состояние.
- Создание проекта (модалка: название, заказчик, дробилка, проба руды, исполнитель).
- Инженерный визард — 3 шага (Геометрия / Грансостав / Продукт) со степпером,
  формами на `Grid`/`Field`/`Input`/`SegmentedControl`, кнопкой «Выполнить расчёт»
  и тост-уведомлением.
- Drawer результатов по каждому шагу — таблица вычисляемых значений.

Все компоненты интерфейса — из `@uralmash/design-system`; правила проекта (`CLAUDE.md`,
`INVENTORY.md`, `src/tokens/README.md` в репозитории дизайн-системы) соблюдены: только
семантические токены, `Stack`/`Box` для отступов, `Text variant` для типографики, состояния
`hover/focus-visible/disabled` заведены самими компонентами системы.

**Оценки в drawer результатов — иллюстративные**, вычисленные из введённых параметров
простыми формулами, а не полной инженерной методикой дробления. Так же было устроено
и в исходном прототипе (расчётные экраны там тоже показывали заглушечные данные) —
интерфейс это явно поясняет пользователю.

## Что осталось (бэклог, вне текущей итерации)

Полный разбор прототипа показал существенно больший объём, чем core-флоу. Сознательно
отложено:

- Упрощённый режим — визард на 4 шага в модалке со сравнением нескольких дробилок.
- Ситовый анализ (расчёт a₀/Va₀ по массам классов).
- Интерактивная SVG-диаграмма камеры дробления с подсветкой полей формы
  (математика есть в `legacy-prototype/uploads/cone-crusher-chamber.html`).
- Регистрация и восстановление пароля (сейчас — заглушки-тосты на экране входа).
- Админ-панель «Пользователи и роли».
- Папки/теги заказчиков, корзина проектов, повторное редактирование посчитанного шага
  (в прототипе — форк проекта вместо перезаписи).
- Экспорт в Excel и печать.
- ~15 второстепенных модалок/поповеров прототипа (пикеры дробилок/проб руды со своими
  фильтрами, пресеты, глоссарий и т. д.).

## Структура

```
src/
  types.ts              общие типы (Project, WizardData, ...)
  data/                 моковые справочники и дефолтные данные визарда
  state/                хуки состояния сессии и проектов (в памяти, без бэкенда)
  domain/estimates.ts   иллюстративные формулы для drawer результатов
  components/           AppShell (шапка сервиса), Toast — композиция поверх примитивов DS
  pages/                экраны: вход, список проектов, модалка нового проекта, wizard/
```

## Наследие прототипа

`legacy-prototype/` — исходный статический прототип «Claude Design» (не React), оставлен
как справочник при переносе оставшихся экранов:

| Путь | Что это |
|---|---|
| `Дробилки КМД-КСД.dc.html` | Основной прототип интерфейса |
| `Canvas.dc.html` | Канвас проекта |
| `Storybook.dc.html` | Витрина компонентов и токенов прежней (ad-hoc) дизайн-системы |
| `_ds/industry-.../` | Прежняя дизайн-система прототипа — не путать с `@uralmash/design-system` |
| `styles.css`, `support.js` | Стили и рантайм прежнего прототипа |
| `uploads/cone-crusher-chamber.html` | Расчёт и SVG-диаграмма профиля камеры дробления |
| `screenshots/` | Снимки экранов из инструмента дизайна, в разметке не используются |

`public/assets/` — изображения, перенесённые в новое приложение (логотип, референсные
схемы камеры дробления).
