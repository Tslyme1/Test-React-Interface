# Уралмаш — подбор конусных дробилок КМД/КСД

React-приложение на дизайн-системе [`@uralmash/design-system`](https://github.com/Tslyme1/design-system).
Перенесено со статического прототипа «Claude Design» (`legacy-prototype/`) — см. ниже, что уже перенесено
и что осталось.

## Как посмотреть и потестировать

Три варианта, от самого быстрого к самому «настоящему»:

1. **Ничего не ставить.** Собранная версия текущей ветки лежит в виде Artifact —
   откройте её прямо в браузере и кликайте: [Дробилки КМД-КСД](https://claude.ai/code/artifact/2b712e1d-ff23-48b6-8eda-c80fa01622b9).
   Это статический снимок на момент сборки — правки в коде сюда сами не попадают,
   нужно пересобирать (`npm run build:demo`) и публиковать заново.
2. **Деплой из GitHub, обновляется на каждый push.** Workflow
   `.github/workflows/deploy-pages.yml` собирает и выкладывает приложение на
   GitHub Pages при пуше в `main` или в эту ветку. **Нужно один раз включить
   вручную:** Settings → Pages → Source → «GitHub Actions» в репозитории —
   без этого шага Actions выведет ошибку «Pages site failed». После этого адрес —
   `https://tslyme1.github.io/Test-React-Interface/`, обновляется сам.
3. **Локально.**
   ```bash
   npm install   # подтягивает @uralmash/design-system из GitHub и собирает её (postinstall)
   npm run dev   # http://localhost:5173
   ```

```bash
npm run typecheck   # типы приложения и тестов
npm run build        # typecheck + сборка в dist/ (обычный деплой)
npm run build:demo   # автономная сборка в dist-demo/index.html — один файл,
                      # без сервера, для Artifact/вложений
```

## Проверки

Прокликивать интерфейс руками после каждой правки не нужно — это делают два слоя,
дешёвый и умный.

### Слой 1: детерминированный

```bash
npm run check   # typecheck + ds:lint + test:e2e
```

| Команда | Что ловит |
|---|---|
| `npm run typecheck` | Типы приложения **и тестов** (`tsconfig.test.json`) |
| `npm run ds:lint` | Обход дизайн-системы: сырой цвет, сырые px, число в объекте стилей, сырой `z-index`, гарнитура напрямую, обращение к несуществующему классу CSS-модуля |
| `npm run test:e2e` | ~40 сценариев Playwright: вход, список проектов, визард, панель результата |

E2E-набор кроме сценариев проверяет сквозные инварианты на каждом экране:

- **пустая консоль** — предупреждения React и промахи по aria всплывают именно там;
- **доступное имя у каждого контрола**;
- **каждая подпись связана со своим контролом** — `<label for>` не должен указывать
  в пустоту. Это отдельная проверка, потому что предыдущая такое не ловит: если
  контрол не принял `id` из `Field`, у кнопки `Select` именем остаётся плейсхолдер,
  и поле выглядит подписанным, не будучи связанным с подписью;
- **нет горизонтальной прокрутки**;
- **в тёмной теме фон не прозрачный**, а текст не совпадает с ним по цвету.

Линтер перенесён из репозитория дизайн-системы с одним отличием: список
разрешённых путей пуст. В самой системе `tokens/` и `primitives/` обязаны
работать с сырыми значениями, в потребляющем приложении такого места нет.
Локальное исключение — комментарий `ds-lint-disable` в той же строке.

Всё это гоняется в CI на каждый push (`.github/workflows/checks.yml`);
при падении отчёт Playwright и скриншоты выкладываются артефактами прогона.

### Слой 2: агент `ui-check`

Тесты не видят, что текст слился с фоном или что отступы разъехались.
Это смотрит агент:

```
> используй агент ui-check
```

Он запускает `npm run check`, разбирает падения (включая скриншоты из
`test-results/`), затем снимает 8 экранов в светлой и тёмной теме
и разглядывает их на предмет тёмной темы, раскладки, ритма отступов,
типографики и согласованности. Возвращает список находок с указанием
экрана и темы — или честное «чисто». Определение агента лежит в
`.claude/agents/ui-check.md`, набор экранов — в `scripts/capture-screens.mjs`.

Снять экраны можно и без агента:

```bash
npm run dev &
npm run screens   # → screenshots-review/*.png
```

## Что перенесено

Перенесён core-флоу: вход и выход, список проектов с поиском и сортировкой, создание
проекта, инженерный визард из трёх шагов со степпером и панель результата по каждому шагу.

Полный инвентарь сценариев — **[SCOPE.md](SCOPE.md)**: 23 готово, 9 частично, 33 осталось,
с пометками о покрытии автотестами и предлагаемым порядком дальнейших работ. Отдельно
стоит смотреть категорию «частично» — там сценарий работает в упрощённом виде и его
легко принять за готовый.

Все компоненты интерфейса — из `@uralmash/design-system`; правила проекта (`CLAUDE.md`,
`INVENTORY.md`, `src/tokens/README.md` в репозитории дизайн-системы) соблюдены: только
семантические токены, `Stack`/`Box` для отступов, `Text variant` для типографики, состояния
`hover/focus-visible/disabled` заведены самими компонентами системы.

Что стоит знать до демонстрации:

- **Проекты хранятся в браузере** (`localStorage`), бэкенда нет — на другом компьютере
  списка не будет.
- **Оценки в панели результата — иллюстративные**, вычисленные из введённых параметров
  простыми формулами, а не полной инженерной методикой дробления. Так же было устроено
  и в исходном прототипе — интерфейс это явно поясняет пользователю.

## Структура

```
src/
  types.ts              общие типы (Project, WizardData, ...)
  data/                 моковые справочники и дефолтные данные визарда
  state/                хуки состояния сессии и проектов (в памяти, без бэкенда)
  domain/estimates.ts   иллюстративные формулы для drawer результатов
  components/           AppShell (шапка сервиса), Toast — композиция поверх примитивов DS
  pages/                экраны: вход, список проектов, модалка нового проекта, wizard/
```

## Наследие прототипа

`legacy-prototype/` — исходный статический прототип «Claude Design» (не React), оставлен
как справочник при переносе оставшихся экранов:

| Путь | Что это |
|---|---|
| `Дробилки КМД-КСД.dc.html` | Основной прототип интерфейса |
| `Canvas.dc.html` | Канвас проекта |
| `Storybook.dc.html` | Витрина компонентов и токенов прежней (ad-hoc) дизайн-системы |
| `_ds/industry-.../` | Прежняя дизайн-система прототипа — не путать с `@uralmash/design-system` |
| `styles.css`, `support.js` | Стили и рантайм прежнего прототипа |
| `uploads/cone-crusher-chamber.html` | Расчёт и SVG-диаграмма профиля камеры дробления |
| `screenshots/` | Снимки экранов из инструмента дизайна, в разметке не используются |

`public/assets/` — изображения, перенесённые в новое приложение (логотип, референсные
схемы камеры дробления).
