# Правила проекта

Этот файл читается при каждой задаче. Правила ниже — не рекомендации.

Составлен по шаблону из [`Tslyme1/ds-skills`](https://github.com/Tslyme1/ds-skills)
и адаптирован под роль этого репозитория: здесь **приложение, потребляющее**
дизайн-систему, а не сама система.

## Что это за проект

Интерфейс подбора конусных дробилок КМД/КСД (Уралмаш) на React + TypeScript + Vite.
Весь интерфейс собирается из [`@uralmash/design-system`](https://github.com/Tslyme1/design-system).
Инвентарь перенесённого и оставшегося — в [`SCOPE.md`](SCOPE.md).

## Перед любой вёрсткой

```bash
npm run ds:docs   # принесёт документацию системы в .ds-docs/
```

1. Прочитай `.ds-docs/INVENTORY.md` — реестр компонентов.
2. Прочитай `.ds-docs/tokens/README.md` — значения ролей токенов и, важнее,
   разделы «когда нельзя».
3. Только после этого пиши код.

Фактическое API компонентов — `node_modules/@uralmash/design-system/dist/index.d.ts`.

## Дизайн-систему отсюда не правят

Система живёт в отдельном репозитории и прорабатывается отдельно. В этом
репозитории её только применяют.

- Не редактируй `node_modules/@uralmash/design-system`.
- Не заводи в приложении собственную копию компонента системы.
- Не хватает компонента или варианта — **остановись и спроси**. Это заявка
  в систему, а не повод собрать замену на месте.

Композиция из существующих компонентов внутри `src/` — это экран, а не новый
компонент системы, и она разрешена. Граница: если получившееся претендует
на переиспользование в других продуктах, это заявка в систему.

## Никогда

- Не пиши hex, `rgb()`, `hsl()`, `oklch()` — нигде в `src/`.
- Не пиши сырые px в CSS для `padding`, `margin`, `gap`, `border-radius`,
  `font-size` — только `var(--space-*)`, `var(--radius-*)`, `var(--text-*)`.
- Не пиши числа в объектах стилей: `style={{ padding: 12 }}`.
- Не ставь `margin` между соседними элементами — только `<Stack gap>`.
- Не задавай фиксированную высоту блокам с текстом.
- Не задавай `z-index` числом — только `var(--z-*)`.
- Не задавай `font-family` напрямую — только `var(--font-heading)` / `var(--font-body)`.
- Не проверяй тему внутри компонента: ни `if (theme === 'dark')`, ни отдельных пропов.
- Не ставь две `primary`-кнопки на один экран.

## Всегда

- Отступы — через `Stack` и `Box`.
- Типографика — через `Text variant`, никогда не `font-size` напрямую.
- Цвет — только семантические роли (`textMuted`, `surfaceRaised`).
- Поля формы — через `Field`, с прокинутыми в контрол `id` и `aria-*`
  из render-пропов. Контрол, который их не принимает (например `SegmentedControl`
  со своим `fieldset`), в `Field` не заворачивается — иначе подпись повиснет
  в пустоте. Это ловится тестом.
  Первое исключение — повторяющиеся строки таблицы (например, редактируемая
  ситовая таблица, собранная из `Grid`/`Stack` с `Input`, раз `Table` не даёт
  режим редактирования ячеек): подпись столбца там одна, в заголовке, а не
  в каждой строке. Контрол в такой строке получает `aria-label` напрямую,
  без `Field`.
  Второе — строка фильтров над каталогом и окно фильтров: назначение написано
  внутри самого поля и служит его доступным именем, а подпись над каждым
  из шести соседних фильтров дублировала бы то же слово и удваивала высоту
  панели. Это исключение именно про условия, стоящие в ряд: в панели
  параметров упрощённого режима они идут столбцом, и там подписи есть —
  вместе с подсказкой, раскрывающей короткую запись величины («n, мин⁻¹»).
- Интерактивные элементы — сразу с `hover`, `focus-visible`, `active`, `disabled`.
- Области с данными — сразу с `loading`, `empty`, `error`.
- После правок — `npm run check`.

## Проверки

```bash
npm run check        # типы + линтер + E2E, всё вместе
npm run typecheck    # приложение и тесты
npm run ds:lint      # обход дизайн-системы
npm run test:e2e     # 206 сценариев Playwright
npm run screens      # 11 экранов × 2 темы в screenshots-review/
```

Нарушение линтера — блокер, а не замечание. Локальное исключение —
комментарий `ds-lint-disable` **в той же строке**, и каждое такое место
стоит обсуждать, а не оставлять молча.

## Агенты

| Агент | Когда |
|---|---|
| `ui-build` | Собрать экран или раздел. Следует скиллу `ds-compose` |
| `ui-check` | Проверить после правок. Следует скиллу `ds-review` |

Скиллы — в `.claude/skills/`. Общие файлы (`src/App.tsx`, `src/types.ts`,
состояние в `src/state/`) агенты не правят: их держит ведущий, иначе
параллельная работа разъедется.

## Когда чего-то не хватает

Остановись и спроси. Опиши:

- какую роль должен закрыть новый токен или компонент;
- какой существующий ближе всего и чем именно не подходит;
- что сломается, если использовать существующий.

Обход системы «на один раз» не бывает одноразовым.

## Что здесь мок, а не продукт

Чтобы это не принимали за незаконченную работу:

- **Авторизация** — демонстрационная, пароль на сервере не проверяется:
  пускает любую пару, а незнакомый логин заводит пользователя на месте.
  Это стенд, и упереться в «нет такой учётной записи» здесь значило бы
  закрыть вход тому, кто просто хочет посмотреть.
- **Этап 1 (геометрия камеры)** — настоящий расчёт по методике НИЛ ПАО
  «Уралмашзавод»: `src/domain/chamberProfile.ts` повторяет девять шагов
  §3.2 подробной документации и воспроизводит контрольный пример §7
  до последнего знака (сторожит `tests/e2e/chamber-profile.spec.ts`).
  Пример проверяется прямо на `computeChamberProfile`, а не через форму:
  зон в нём три, а форма спрашивает одну или две — предел стоит на вводе
  (`ZoneCount`), а не в методике, и сам расчёт числом зон не ограничен.
  Значения формы по умолчанию — те же числа §7, только без третьей зоны.
  Профиль считается рекурсией от разгрузочной кромки, поэтому D, H, l₂,
  β₂ и S₀ — исходные данные, а радиус-векторы r и их углы α — результат,
  и в форме их не спрашивают.
- **Этапы 2 и 3** — по-прежнему иллюстративные оценки из введённых
  параметров, а не инженерная методика дробления. Так было и в исходном
  прототипе.
- **Проекты** хранятся в `localStorage` браузера, бэкенда нет: на другом
  компьютере списка не будет. При первом запуске список заполняется примерами —
  очищенный список примерами больше не заполняется.
- **Справочники дробилок и проб руды** правятся из приложения («+ Новая»
  и карандаш в строке), но правка — это **наложение** поверх каталога
  (`src/domain/catalogEdits.ts`), и лежит она там же, в `localStorage`
  (`src/state/userCatalog.ts`). Сам каталог в `src/data/` не меняется:
  так видна разница «было → стало», которую показывают под таблицей,
  и так правка не выдаёт себя за паспортные данные завода.
